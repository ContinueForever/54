# RFC1195
# RFC 1195 - 在 OSI IS-IS 中携带 IP 和 ISO 路由

IS-IS 最初为 ISO CLNP 设计，RFC 1195 扩展了 IS-IS 以支持 IPv4/IPv6 路由，引入以下关键 TLV：

- **TLV 128 (IP Internal Reachability)**：宣告直连 IPv4 前缀。
- **TLV 129 (Protocols Supported)**：宣告支持的协议族（NLPID = 0xCC 表示 IPv4）。
- **TLV 130 (IP External Reachability)**：宣告外部引入的 IPv4 路由。
- **TLV 132 (IP Interface Address)**：宣告接口 IP 地址。

## 诊断相关要点

| 症状 | 可能原因 |
|------|----------|
| IP 路由不发布 | 缺少 Protocols Supported TLV 或 NLPID 不匹配 |
| 外部路由不可达 | IP External Reachability TLV 缺失或 down-bit 置位 |
| 邻居 UP 但无 IP 路由 | 接口未使能 IS-IS 或地址族未协商 |

# RFC3358
# RFC 3358 - IS-IS 邻接关系与状态机

IS-IS 邻接按如下状态机演进：

```
Down -> Init -> Up
```

## 关键状态

- **Down**：未收到任何 IIH 或 Hold Timer 超时。
- **Init**：收到 IIH，但邻居列表中未看到自己 System ID。
- **Up**：双向通信确认，邻居列表中包含自己 System ID。

## 影响邻接的常见故障

| 故障类型 | 典型现象 |
|----------|----------|
| 区域不匹配 | 收到 IIH 但 Area Address TLV 不一致，邻接无法到达 Up |
| 认证失败 | IIH 被丢弃，序列中看不到任何邻接状态变更 |
| Hello 定时器不匹配 | 短期可能不影响邻接，长期导致保活抖动 |
| Circuit Type 不匹配 | L1/L2 级别不一致，邻接状态停滞 |
| 重复 System ID | LSP 冲突、多次邻接震荡 |
| MTU 不匹配 | LSP 分片交互异常，邻接反复 Init |
| 链路物理 down | 对端停止发送 IIH，本端 Hold Timer 超时后 Down |

## 诊断规则

- 若 fault 段 src_ids 减少且邻接日志出现 adjacency_down，判定为 NEIGHBOR_LOSS_AT_FAULT。
- 若 fault 段持续收到 IIH 但邻接不 Up，检查 Area、Auth、Circuit Type、MTU。
- 若出现 duplicate_system_id 标志且多个节点共享同一 System ID，判定为 DUPLICATE_SYSTEM_ID。

# RFC5301
# RFC 5301 - IS-IS 动态主机名

动态主机名映射 System ID 到可读名称，通过 **TLV 137 (Dynamic Hostname)** 携带。

## 诊断价值

- 通过 System ID 反查主机名，便于定位故障节点。
- 若日志或 pcap 中出现 System ID 冲突，可结合主机名快速定位网元。

## 表格

| System ID | Hostname | Role |
|-----------|----------|------|
| 0000.0000.0001 | R01 | 星型中心 |
| 0000.0000.0002 | R02 | 焦点节点 |
| 0000.0000.0003 | R03 | 背景节点 |
| 0000.0000.0004 | R04 | 背景节点 |
| 0000.0000.0005 | R05 | 背景节点 |
