# IS-IS 故障分析工作台（离线可视化）

## 打开

用桌面浏览器打开 `dist/index.html`，或解压离线包后打开其中的 `index.html`。
页面内嵌数据、样式和脚本，不需要启动分析后台、GraphRAG 或模型服务。

## 这次调整

页面以一条已完成的故障分析任务为入口，展示项目如何读取输入、提取证据、查询知识、分层检查并生成报告。
默认显示完整结果，不再以七类 skill 的逐页介绍作为主线。

“分析已完成”不等于“现场故障已修复”。现有记录保存了诊断与报告，没有保存现场配置操作或业务恢复验证，因此处置状态明确保持未验证。

## 查看方式

### 任务详情

顶部显示任务编号、输入与完成时间；处理链遵循历史 trace 的实际顺序：

加载输入 → 特征提取 → 查询知识 → 物理层检查 → 链路层检查 → 路由层检查 → 应用层检查 → 生成报告。

- 点击处理节点，右侧同步显示该步骤的输入、输出、原始事件与证据。
- 点击“复盘分析过程”，按处理顺序重新展开已保存结果；可暂停或调整速度。
- 拖动进度条定位到任一步骤，报文信号、知识依据和分层结果随进度展开。
- “查看完整结果”直接返回分析完成状态。
- 基线、异常、恢复样例按钮切换合成抓包窗口；这与分析执行进度是不同时间轴。
- flow-tracer 的全程记录入口显示事件与执行错误数量。

### 执行记录

查看原始 16 条事件、时间、层级和状态。FAIL 表示检查命中了规则，不表示程序崩溃。

### 输入与证据

查看或下载抓包、日志、协议特征和规则材料，按窗口筛选 R02 的报文字段。

### 诊断报告

展示判断依据、建议处置与复核步骤，以及与原报告的勘误区别。可打开未修改的原件。

### 知识维护记录

独立展示 material-to-csv、knowledge-builder、kg-validator 的补跑记录：候选提取、82 → 87 个节点的构建和分级校验。
它们不是本次诊断任务的必经步骤；已有知识支持诊断时，不需要每次故障都重新导入或构建。

## 技能职责的呈现

- workspace-orchestrator：组织处理顺序与阶段交接，见处理链的“流程组织职责”。原历史 trace 没有独立编排调用或人工检查点，页面不伪造该历史。
- isis-analysis：读取数据、提取特征、分层检查、形成报告，对应处理链多数节点。
- knowledge-bridge：加载已配置的知识表并查询相关节点，对应“查询知识”。
- flow-tracer：贯穿整个分析过程记录事件，并非最后才记录。
- material-to-csv、knowledge-builder、kg-validator：位于独立知识维护视图，以真实补跑产物展示作用。

## 来源与边界

- 诊断、trace 和时序图来自 `run_20261013_200713`，分析时间为 2026-10-13 20:07:13。
- 页面中的“案例任务”是对该案例的业务描述，不是原 trace 中独立记录的用户报障事件。
- 抓包和日志来自项目归档的同场景合成样例；历史临时输入已不再保留，因此不宣称它们与历史输入逐字节相同。重新解析字段与报告信号相符。
- 知识准备于 2026-10-14 在演示副本补跑；原项目知识表、诊断规则和历史报告未改。新增五个节点是既有规则的知识表示，不代表五种新故障，也不自动更新诊断规则。
- 历史分析采用 CSV 查询，关闭模型调用。本包没有实时 GraphRAG、模型推理、索引重建或持续学习记录。
- 原报告将同一故障的两层规则命中误判为复合故障。展示解读已纠正，原件保留。
- 日志第一行方向表述与抓包不完全一致；解读依据抓包字段和第二行日志，差异见 `evidence/interpretation.md`。
- after 段表示合成报文字段恢复，不代表现场修复或业务恢复验证。
- 技能名称是职责对应；原 trace 不是独立 skill 调用审计。原始结构化结论中的 unknown 与空 affected_nodes 保留。

## 文件

- `dist/index.html`：独立工作台页面。
- `dist/evidence/`：原件、演示副本前后表、补跑日志、查询与校验结果。
- `dist/讲解说明.md`：本说明的交付副本。
- `dist/verification.json`：数据、页面交互和交付检查记录。
- `previous-version/`：调整前页面与说明，仅用于对照，不在交付包中。

## 维护

只改页面时执行 `python3 demo/skill-replay/build_page.py`，再运行 `python3 demo/skill-replay/verify_package.py`。
无需再次补跑知识处理。`prepare_data.py` 用于从项目材料重新制作演示数据副本。
