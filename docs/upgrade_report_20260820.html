升级目标（对应甲方要求）

  • 核心诉求Hermes（LLM）在分析流程关键环节全程参与思考与判断——告别"一键黑盒"，让甲方在每个阶段看到 LLM 的观察、推理与决策过程。
  • 能力补齐复合故障诊断——两个独立故障在同一窗口叠加时，须分别识别各子故障证据并按规则逐项排查。
  • 质量保障批判性审查——批判子智能体对诊断报告独立审查，保障结论质量。

关键决策

决策点选择理由
LLM 参与方式 Hermes 执行 skill 流水线时多阶段介入（每阶段输出推演记录）；脚本内保持单次 LLM 辅助诊断 体现 LLM 思考能力；避免脚本内多次调 LLM 形成新的黑盒
诊断 LLM 硅基流动 Qwen/Qwen2.5-72B-Instruct kimi-k3 配额失效（HTTP 401）；Qwen2.5 无思考模式、JSON 输出稳定
批判性审查 批判子智能体（isis-critic）按检查清单独立审查 独立审查者立场，输出结构化批判意见（CRITICAL→INFO 分级）
GraphRAG 模型 Qwen/Qwen2.5-72B-Instruct + local_tfidf 本地向量 与诊断引擎统一；embedding 本地化免外部依赖（离线环境）

02复合故障诊断（11 组场景）

新增 isis-simulator/src/isis_simulator/scenarios/combo_lib.py， 定义 COMBO_FAULTS——每组复合场景在同一故障窗口叠加两个独立故障，

  • pcap：两个故障特征叠加的网络报文（如认证失败 + 邻接 Down）
  • 合并日志：双故障事件文本交错（如 MTU 不匹配 + Circuit type 不匹配）

03LLM 全程参与（9 阶段推演）

skills/workspace-orchestrator/SKILL.md（v3.0.0）将流水线拆分为 9 个阶段， run.py 支持 --stage 单阶段执行。Hermes 在每个阶段之间 必须输出 【Hermes 推演 · 阶段名】记录，包含三要素：

① 看见了什么（观察）
简明列出该阶段产物的关键数值、事件与信号
② 我的判断（推理）
基于观察给出初步判断、可能原因与风险点
③ 下一步决策（决策）
说明选择下一步的原因、预期结果与验证方式

流水线示例（link-down 场景）

阶段 1 · 生成数据
run.py link-down --run-id demo_run --stage generate
【Hermes 推演 · 生成数据】读取 pcap/log 文件清单与大小，预估异常注入阶段与可能的故障类型。
阶段 2 · 准备输入
run.py link-down --run-id demo_run --stage prepare
【Hermes 推演 · 准备输入】确认 pcap 与 log 成对、数量吻合；缺文件则说明处理。
阶段 3 · 构建知识
run.py link-down --run-id demo_run --stage build_knowledge
【Hermes 推演 · 构建知识】阅读 nodes.csv，确认复合故障节点在库，说明其诊断价值。
阶段 4 · 构建索引
run.py link-down --run-id demo_run --stage build_index
【Hermes 推演 · 构建索引】说明索引规模变化与查询时延预估。
阶段 5 · 启动 GraphRAG
run.py link-down --run-id demo_run --stage start_rag
【Hermes 推演 · 启动服务】确认 /health 正常、索引与模型配置。
阶段 6 · 运行分析
export GRAPHRAG_ENABLED=true && python3 -m agent_analysis --input agent-analysis/data/incoming/demo_run
【Hermes 推演 · 规则匹配】逐一核对命中规则依据、误报可能与复合故障完整性。
【Hermes 推演 · LLM 诊断】评价 LLM 结论与命中规则、知识引用的证据链一致性。
阶段 7 · 批判性审查（必需）
run.py link-down --run-id demo_run --stage critic
【Hermes 推演 · 批判审查】汇总批判子智能体问题清单，说明采纳 / 拒绝理由。
阶段 8 · 汇总呈现
run.py link-down --run-id demo_run --stage report
【Hermes 推演 · 总结交付】综合报告、批判意见与自身判断输出最终结论及可信度标注。
阶段 9 · 前端展示（可选）
run.py link-down --run-id demo_run --stage frontend
启动 http://localhost:8080。
设计说明：LLM 的参与体现在 Hermes 执行流水线各阶段的主动推理， 而非脚本内多次调用 LLM。engine.py 已回滚为单次 LLM 辅助诊断（保留复合故障判定等确定性标注）， 避免"脚本内黑盒化"。

04批判性审查（isis-critic 子智能体）

Hermes 执行完整工作流后，必须启动批判性子智能体（isis-critic）对诊断报告独立审查——

  • 基于 skills/workspace-orchestrator/references/critic-checklist.md 逐项核查
  • 分 6 大核查域：数据完整性 / 特征提取 / 规则命中 / 知识引用 / LLM 结论质量 / 复合故障专项
  • 输出结构化批判意见至 agent-analysis/output/reports/run_<ts>.critique.md

问题等级定义

等级含义处置
CRITICAL结论与证据相悖，或存在明显漏判必须修正后重新出结论
MAJOR证据不足、归因不唯一、缺少必要排查步骤应补充证据或修正结论
MINOR表达不清、格式问题、参考文献缺失建议改进，不阻塞结论
INFO观察性建议、可操作优化仅供参考
强制规则：批判性审查为必需步骤；若批判子智能体不可用， Hermes 应停止流程并说明原因，不得直接交付未经审查的结论。

07过程修复（本轮发现并解决）

1

场景名静默失败：CLI 需精确场景名（hello-timer 应为 hello-timer-mismatch），未知场景静默跳过不报错

修复：统一场景名注册与文档（GUIDE 场景表已更新），CLI 层补精确名映射

2

runner 路径解析错误：相对路径导致生成产物落于 isis-simulator/isis-simulator/output/

修复：generate_isis_scenario 增加 output_dir.resolve()

3

GraphRAG 解释器缺失：微软 GraphRAG 依赖安装于 graphrag/.venv，系统 python 找不到模块

修复：runner 增加 graphrag_python()，优先使用 venv 解释器构建索引 / 启动服务

4

Qwen 思考模式导致 content 为空：Qwen3.5 默认返回 reasoning_content 而 content 为空

修复：客户端请求加 enable_thinking=false + 响应 JSON 解析回退；GraphRAG chat 模型切换到 Qwen2.5-72B（无思考模式）

5

诊断 LLM 失效：kimi-k3 配额过期（HTTP 401）

修复：经确认切换至硅基流动 Qwen（agent-analysis/.env.project），已端到端验证
