# 大模型辅助诊断 · 证据解读示例

本解读由 Codex 根据本次项目特征、规则、知识和状态快照编写，用于呈现模型环节的作用；未向项目配置的模型接口发送请求。

## 最可能的原因

R02 在配置变更后，进程 is-type 和接口 circuit-type 均由 level-2-only 变为 level-1；R01 保持 level-2-only。两端在这条链路上失去共同的 IS-IS 层级，导致原 L2 邻接不能继续维持。这是本例证据最充分的根因。

## 证据关联

1. 抓包正常窗口中，R01 与 R02 各发送 10 条 L2 Hello；异常窗口中，R01 仍有 10 条 L2 Hello，R02 改为 10 条 L1 Hello。Hello 间隔均为 3 秒，Holding 均为 27 秒。
2. 设备状态快照与报文一致：R02 变更后的有效层级为 L1，R01 为 L2。日志在 T+40 秒记录 R02 配置提交及本地邻接失效，在 T+55 秒记录 R01 邻接因保持时间到期而中断。
3. R01 到业务环回地址 10.20.2.1 的探测从 10 次请求、10 次应答变为 10 次请求、0 次应答；状态快照中对应 IS-IS 路由由存在变为缺失。
4. L2-R003 与 L3-R004 指向同一 circuit_type_mismatch；L2-R001 记录邻接中断，L4-R001 记录业务探测退化。共四条规则命中、三个候选模式，证据支持一个主根因及其后果，不能将四条命中计作四个独立故障。

## 候选原因比较

- 层级配置变更：抓包、配置快照和提交事件三项一致，优先检查。
- 物理断链：快照中接口仍为 UP、CRC 与输入错误为 0，且仍可观测双方 Hello，不支持本例由完整物理断链引起；有限快照不能排除所有间歇性物理问题。
- 区域地址问题：两端快照与抓包区域地址相同；本例原目标为 L2 邻接，区域不同本身也不直接阻止 L2 邻接。
- 认证问题：两端快照均未启用认证，观测 Hello 中未携带认证 TLV，本例没有认证失败证据。
- MTU、ACL 或其他转发问题：两端 MTU 相同、Hello PDU 长度稳定；这些因素不是目前解释层级变化的首选原因。不能仅凭丢包和零错误计数排除所有转发问题。
