# Hermes 提示词手册 — 供甲方工作人员使用

> **用途**: 帮助甲方技术人员快速了解项目、进行二次开发
> **使用方式**: 将以下提示词复制到 Hermes 对话中发送
> **适用对象**: 甲方开发团队、运维人员、技术负责人

---

## 提示词 1：项目全景速览（首次接触）

```
我是甲方技术人员，第一次接触 agent-analysis 项目。请帮我快速了解：

1. 这个项目是做什么的？核心目标是什么？
2. 我们甲方需要做什么？你们（开发方）负责什么？边界在哪里？
3. 项目目录结构是怎样的？每个目录是做什么的？
4. 有哪些关键配置文件？它们的作用是什么？
5. 当前项目的完成度如何？哪些功能已经可用，哪些还在开发中？

请以清晰的层级结构输出，方便我快速建立整体认知。
```

**预期输出**: 项目概览、职责边界、目录说明、配置清单、完成度评估

---

## 提示词 2：快速上手运行（想立即试试）

```
我想在本地快速运行一次分析流程，看看效果。请告诉我：

1. 运行前需要准备什么？（环境、数据、配置）
2. 最简单的运行命令是什么？
3. 运行后在哪里看结果？
4. 如果我想用测试数据而不是真实数据，怎么操作？
5. 常见报错和解决方法？

请给出可以直接复制的命令，我按步骤执行。
```

**预期输出**: 环境检查清单、分步命令、结果查看路径、测试数据准备、排错指南

---

## 提示词 3：修改诊断规则（自定义规则）

```
我想修改/添加一条 IS-IS 诊断规则。请指导我：

1. 规则文件在哪里？格式是什么样的？
2. 如何添加一条新规则？请给我一个完整的示例
3. 规则中的 indicators 怎么写？如何匹配实际数据？
4. 修改后需要重启什么吗？还是立即生效？
5. 如何验证我的新规则是否生效？

请用我当前项目中的实际路径和文件内容来举例。
```

**预期输出**: 规则文件位置、JSON格式说明、完整示例、生效机制、验证方法

---

## 提示词 4：调整分析流程（增删检查步骤）

```
我想调整分析流程，比如跳过某些层的检查，或者调整检查顺序。请告诉我：

1. 分析流水线配置文件在哪里？
2. 如何启用/禁用某个检查步骤？
3. 如何调整步骤的执行顺序？
4. 每个步骤的 module 字段是什么意思？可以自定义吗？
5. 修改后如何验证流程是否按预期执行？

请结合我项目中的 default_pipeline.json 实际内容来解释。
```

**预期输出**: 流水线配置路径、enabled开关用法、顺序调整方法、module说明、验证方式

---

## 提示词 5：更新知识库（接入甲方知识图谱）

```
我们甲方有大模型生成的知识图谱表格（CSV格式），想接入到系统中。请指导我：

1. 知识表格应该放在哪个目录？
2. 表格的格式要求是什么？有哪些必填字段？
3. 节点表（nodes.csv）和边表（edges.csv）的关系是什么？
4. 如何验证表格是否被正确加载？
5. 如果表格格式不对，会有什么报错？怎么排查？

请展示我项目中 knowledge_tables 目录下的文件结构和示例内容。
```

**预期输出**: 目录位置、CSV格式规范、表关系说明、验证命令、排错指南

---

## 提示词 6：开发新 Skill（扩展功能）

```
我想为项目开发一个新的 Skill，用于 [描述你的需求，例如："分析BGP协议数据" 或 "生成周报"]。请指导我：

1. Skill 应该创建在哪里？目录结构是什么？
2. SKILL.md 文件怎么写？必须包含哪些内容？
3. 如何让 Hermes 加载我的新 Skill？
4. 如何在 Skill 中调用甲方的本地 vLLM 模型？
5. 有没有现成的 Skill 可以作为参考？

请结合我项目中已有的 Skill（如 isis-analysis）作为示例来讲解。
```

**预期输出**: Skill目录结构、SKILL.md模板、加载方法、vLLM调用示例、参考案例

---

## 提示词 7：查看分析结果和时序图（理解输出）

```
我刚运行了一次分析，想看看结果。请告诉我：

1. 诊断报告在哪里？怎么阅读？
2. 时序流程图在哪里？怎么打开？
3. 追踪记录（trace）文件包含什么信息？
4. 如果分析发现了异常，报告中会怎么呈现？
5. 如何把报告分享给其他人？

请用我项目中实际生成的文件来展示和说明。
```

**预期输出**: 报告路径、阅读指南、HTML打开方式、trace结构说明、分享方法

---

## 提示词 8：排查问题（遇到报错）

```
我遇到了一个问题：[描述你的问题，例如 "运行 make diagnose 报错" 或 "Hermes 没有加载我的 Skill"]

请帮我排查：

1. 可能的原因是什么？
2. 需要检查哪些文件/配置？
3. 如何查看日志和错误信息？
4. 常见的解决方法有哪些？
5. 如果还是解决不了，需要提供什么信息给你们（开发方）？

请结合我项目的实际路径和配置文件来指导排查。
```

**预期输出**: 原因分析、检查清单、日志位置、解决方法、反馈模板

---

## 提示词 9：了解技术演进路线（规划未来）

```
我想了解这个项目的技术演进计划，以便我们甲方做长期规划。请告诉我：

1. 当前项目处于哪个阶段？
2. 未来有哪些 planned 的功能升级？
3. GraphRAG 和 OWL 本体方案是什么？什么时候会用到？
4. 从当前阶段演进到下一阶段，需要我们甲方做什么准备？
5. 每个阶段的投入（人力、时间、资源）大概是怎样的？

请结合 docs/transition_roadmap.md 的内容来讲解。
```

**预期输出**: 当前阶段、演进路线、技术方案说明、甲方准备事项、投入估算

---

## 提示词 10：项目交接和培训（团队 onboarding）

```
我需要给团队其他成员介绍这个项目，让他们能快速上手。请帮我准备：

1. 项目的核心价值是什么？一句话怎么描述？
2. 团队成员需要掌握哪些前置知识？（IS-IS、Python、Hermes？）
3. 推荐的学习路径是什么？先看什么后看什么？
4. 有哪些文档是必须阅读的？阅读顺序是什么？
5. 有没有快速验证环境是否正常的 checklist？

请输出一份适合打印或分发的 onboarding 指南。
```

**预期输出**:  elevator pitch、前置知识清单、学习路径、文档阅读顺序、环境检查清单

---

## 通用提示词模板（自由提问）

如果以上提示词都不匹配你的需求，可以使用以下模板：

```
我是甲方技术人员，当前在 agent-analysis 项目中工作。

我的问题是：[清晰描述你的问题]

我当前的操作环境是：
- 工作目录：[例如 /opt/agent-analysis]
- 操作系统：[例如 CentOS Stream 10]
- 我的角色：[例如 开发/运维/管理]

请结合我项目中的实际文件和配置来回答，给出可以直接执行的命令或修改建议。
```

---

## 使用建议

| 场景 | 推荐提示词 |
|------|-----------|
| 第一次接触项目 | 提示词 1 |
| 想立即跑起来看看 | 提示词 2 |
| 要改诊断规则 | 提示词 3 |
| 要调整分析流程 | 提示词 4 |
| 要接入甲方知识 | 提示词 5 |
| 要开发新功能 | 提示词 6 |
| 要看分析结果 | 提示词 7 |
| 遇到报错 | 提示词 8 |
| 做长期规划 | 提示词 9 |
| 培训团队成员 | 提示词 10 |

---

> **提示**: Hermes 会自动读取项目中的 `AGENTS.md` 和 `.hermes/skills/` 下的 Skill 定义，因此以上提示词会结合项目实际内容给出回答，而不是通用回答。
