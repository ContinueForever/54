# AGENTS.md — 54所卫星网络IS-IS智能分析系统

## 项目身份

- **名称**: 54所卫星网络IS-IS智能分析系统
- **代号**: agent-analysis
- **环境**: CentOS Stream 10, 完全离线, 内网vLLM
- **模型**: Qwen3.5-35B-A3B @ 192.168.1.80:9998
- **核心定位**: 接收甲方云平台提供的网络数据，进行分层智能分析，辅助开发人员定位故障

## 工作边界

| 我们负责 | 甲方云平台负责 |
|---------|--------------|
| 分析pcap、log、状态数据 | 拓扑管理、故障注入、数据采集 |
| 分层诊断、生成报告 | 网络运维、配置变更 |
| 时序流程图、辅助定位 | 基础设施维护 |

**绝不涉及**: 拓扑操作、故障注入、容器管理、SSH到甲方设备执行命令

## 信息分类与存储规则

当会话产生以下类型信息时，必须分类处理：

| 级别 | 判定标准 | 存储位置 | 是否持久化记忆 |
|------|---------|---------|--------------|
| CRITICAL | 架构决策、诊断框架变更、API契约 | `docs/decisions/` + memory() | 是 |
| IMPORTANT | 新故障模式发现、诊断规则改进、知识库更新 | `config/` + memory() | 是 |
| CONTEXT | 背景信息、环境说明、临时调研 | `docs/context/` | 可选 |
| TEMP | 临时调试、一次性查询、中间计算结果 | `data/temp/` | 否，7天清理 |

## 操作约束

1. **离线环境**: 禁止尝试任何联网操作（下载、更新、API调用到外部）
2. **vLLM调用**: 温度固定0.1，max_tokens 2048，确保确定性输出
3. **磁盘监控**: 操作前检查磁盘使用率，超过95%时告警并停止写入
4. **数据只读**: 对甲方提供的数据文件只读，分析结果写入 `output/` 目录
5. **规则优先**: 诊断时优先使用 `config/diagnosis_rules/` 中的确定性规则，规则未覆盖时才调用LLM

## 质量检查点

每次分析完成后必须验证：
- [ ] 追踪记录 `data/traces/` 已生成且JSON有效
- [ ] 时序流程图 `output/sequence_diagrams/` 已生成
- [ ] 诊断报告 `output/reports/` 已生成
- [ ] 磁盘使用率 < 95%
- [ ] 无异常报错信息

## 记忆策略

### 必须保存（memory target="memory"）
- 甲方环境约束（vLLM地址、磁盘状况、网络限制）
- 诊断规则变更历史
- 知识表格格式约定
- 与甲方协作的约定事项

### 必须保存（memory target="user"）
- 用户偏好（报告格式、输出详细程度）
- 用户角色（开发人员/专家/管理员）
- 用户关注的特定节点或场景

### 绝不保存
- 单次分析的原始数据或中间结果
- 临时调试信息
- 会话进度或任务状态
- 7天内会过期的信息

## 诊断流程标准

```
1. 读取 config/analysis_pipeline/default_pipeline.json
2. 按顺序执行启用的检查步骤
3. 每层检查调用对应的 config/diagnosis_rules/ 规则
4. 记录每个步骤的追踪点（PASS/FAIL/DONE）
5. 遇到异常时：
   a. 规则覆盖 → 直接输出诊断结论
   b. 规则未覆盖 → 调用LLM辅助诊断
6. 生成时序流程图（Mermaid格式）
7. 输出诊断报告
```

## 与甲方协作要点

- 知识图谱以表格形态（CSV）由甲方提供，存放于 `config/knowledge_tables/`
- 诊断规则以JSON形态存放于 `config/diagnosis_rules/`，甲方可直接编辑
- 分析流水线以JSON形态存放于 `config/analysis_pipeline/`，甲方可调整步骤
- 所有配置变更无需重启Hermes，下次分析自动生效
